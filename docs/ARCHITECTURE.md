# Архитектура

## Назначение

Dorm Campus — модульная платформа для общежития с тремя пользовательскими контурами:

1. личный кабинет студента;
2. рабочее место сотрудников общежития;
3. сводный кабинет руководства.

Мобильное приложение выбирает интерфейс по роли пользователя. Сотрудникам также доступна отдельная desktop-панель.

## Компоненты

### API

`apps/api` предоставляет REST API и события Socket.IO. Express отвечает за маршруты и контроль доступа, Prisma — за работу с данными, Multer — за локальную загрузку изображений.

Основные группы маршрутов находятся в `apps/api/src/routes`. Проверка JWT и ролей централизована в `apps/api/src/auth.ts`.

### Мобильное приложение

`apps/mobile` — Expo/React Native приложение. Навигационное дерево в `src/navigation/RootNavigator.tsx` разделяет STUDENT, ADMIN и LEADERSHIP. Общие визуальные компоненты находятся в `src/components`, состояние сессии, темы, языка, сокетов и уведомлений — в `src/state`.

### Веб-панель

`apps/admin` — Vite SPA для сотрудников общежития. Она использует тот же API-клиент и доменные типы, что мобильное приложение.

### Общий пакет

`packages/shared` — контракт между клиентами и сервером. Изменения DTO и перечислений сначала вносятся сюда, затем поддерживаются в API и интерфейсах.

## Данные и файлы

Разработка по умолчанию использует SQLite. Локальная база не хранится в Git. Начальные демонстрационные данные создаёт `apps/api/prisma/seed.ts`.

Загруженные изображения сохраняются в `apps/api/uploads` и доступны через `/uploads`. Для production рекомендуется S3-совместимое объектное хранилище и CDN.

## Realtime

Socket.IO доставляет новые сообщения и уведомления. REST остаётся источником полного состояния, поэтому клиент после переподключения может повторно загрузить актуальные данные.

## Роли и доступ

- `STUDENT` — личный кабинет и функции проживающего;
- `ADMIN` — данные только своего общежития и административные действия;
- `LEADERSHIP` — агрегированная сводка по общежитиям;
- `residentRole` — дополнительные полномочия студента: староста этажа, инспектор, редактор новостей или регистратор.

Проверка роли должна выполняться на сервере. Скрытие кнопки в интерфейсе не является защитой.

## Точки интеграции

В демонстрационной версии внешние системы заменены локальными реализациями:

| Интеграция | Текущее поведение | Что заменить |
| --- | --- | --- |
| Университетский SSO | локальные пользователи и JWT | OAuth 2.0 / OIDC адаптер в `routes/auth.ts` |
| Платежи | локальная запись операции | платёжный провайдер, webhook и идемпотентность |
| Учебные данные | seed Prisma | API учебной информационной системы |
| Документы института | регистрация заявки | интеграция с документооборотом |
| Хранилище фото | локальный каталог | объектное хранилище |
| Карта | OpenStreetMap + внешние маршруты | допустимый для организации картографический провайдер |

Интеграции следует оформлять отдельными сервисами или адаптерами, сохраняя текущие DTO в `packages/shared`. Это позволяет менять поставщика без переписывания экранов.

## Масштабирование

Для пилота SQLite достаточно. Для нескольких общежитий с одновременной работой пользователей рекомендуется PostgreSQL, внешнее хранилище файлов, Redis-адаптер Socket.IO, централизованные логи и фоновые задания для рассылок.
